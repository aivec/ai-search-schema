# v1.3.3

**Release date**: 2026-11-05

## Security

- Entries of posts that are not public are now checked every time `/llms.txt` is served. Entries of posts changed while the plugin was deactivated, and entries restored by saving an old settings screen, are no longer served

## Changed

- Entries of posts that are not public are no longer deleted from the saved llms.txt content. They are hidden when `/llms.txt` is served, so publishing a post again brings its entry back, including any hand-written text. Hidden entries are listed on the settings screen. An entry is deleted only when its post is permanently deleted
- When a post's slug changes, the URL in its saved llms.txt entry is updated, including the entries of its child pages
- An llms.txt entry whose URL matches no post is hidden if a post with the same title is not public, so that its excerpt is not served after a URL change. Links to another host or port, or to a path outside this site's directory, are hidden only if the title and the last part of the URL, either the slug or the post ID, both match a post that is not public. Links to another site in a subdirectory multisite network are not hidden unless their path matches a post that is not public
- Known limits of llms.txt hiding: an entry with no matching post is hidden by mistake if it shares its title with a post that is not public and links inside this site's directory, or if it also shares the slug or post ID and links anywhere. A link to another port is hidden if its path matches a post that is not public. A link without `http://` or `https://`, such as `example.com/docs/`, counts as a link inside this site. Changing a post's category does not update its entry when the permalink contains `%category%`. After moving a site to another domain, port, or directory, an entry with the old URL is not hidden if its title was edited, and it stays after its post is permanently deleted, so correct it or use the Regenerate button
- Broken llms.txt URLs from earlier versions are repaired the first time an administrator opens the dashboard after updating
- The LocalBusiness subtype in the settings is now chosen from a list of 152 schema.org types instead of being typed in. A saved value that is not on the list is kept and a notice appears in the settings, and the JSON-LD outputs `LocalBusiness` until another type is chosen. This includes types that are not LocalBusiness subtypes, such as `Museum` and `VeterinaryCare`. Developers can add types with the `avc_ais_local_business_types` filter
- Removed unused internal code, including the duplicate class in `src/ContentResolver.php`

## Fixed

- Fixed the front page JSON-LD using `HomePage`, which does not exist in schema.org. It now uses `WebPage`
- Fixed four business types in the setup wizard that do not exist in schema.org. `Cafe` is now `CafeOrCoffeeShop`, `FitnessCenter` is now `ExerciseGym`, `HealthAndBeautySpa` is now `DaySpa`, and `HomeAndConstruction` is now `HomeAndConstructionBusiness`. Saved values are converted automatically
- Fixed public holidays in opening hours being output as `PublicHoliday`. The JSON-LD now uses `PublicHolidays`
- Fixed the setup wizard not showing the saved business type and resetting it to `LocalBusiness` when submitted again
- Fixed backslashes being removed from settings fields when saving
- Fixed some HTML tags being left in JSON-LD text
- Fixed network-wide activation and deactivation on multisite only updating `/llms.txt` on the current site
- Fixed the admin menu having no icon. The menu now shows the AIVEC symbol in the colors of the admin color scheme
